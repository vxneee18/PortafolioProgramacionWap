1. Configuración de Entorno y Descubrimiento

Fundamento Teórico: La arquitectura de red host-only o Red NAT permite segmentar el tráfico entre máquinas virtuales, simulando un enlace de área local físico. En este segmento, las direcciones IP se resuelven a nivel de capa de enlace (L2) usando el protocolo ARP (Address Resolution Protocol), enviando tramas broadcast para correlacionar direcciones IP lógicas con direcciones físicas MAC.

Aislamiento en Red NAT

Se vinculó la máquina atacante (Kali Linux) y la víctima (Snakeoil) bajo el mismo switch virtual NAT para evitar interacción no autorizada en la red local física.

2. Escaneo y Detección de Servicios

Fundamento Teórico: La técnica TCP SYN Scan (-sS) envía paquetes SYN a los puertos objetivo sin culminar el saludo de tres vías (3-Way Handshake). Respuestas SYN/ACK indican puertos abiertos, reduciendo la saturación de conexiones completas y permitiendo deducir las versiones de los servicios concurrentes. 
sudo nmap -p- -sV -sC -T4 10.0.2.4 -oN escaneo_snakeoil.txt

3. Fuzzing de Endpoints Web

Fundamento Teórico: El fuzzing de directorios web envía peticiones HTTP iterativas usando listas de palabras comunes para detectar rutas no indexadas. La evaluación de los códigos de respuesta del servidor (RFC 7231) permite categorizar el comportamiento: 200 OK indica lectura directa, 405 Method Not Allowed señala restricciones en los verbos HTTP, y 500 Internal Server Error denota fallas en la lógica del backend. 
gobuster dir -u http://10.0.2.4:8080 -w /usr/share/wordlists/dirb/common.txt -t 30

4. Interacción con API REST y Tokens JWT

Fundamento Teórico: Las APIs REST manejan estados sin sesión recurriendo a tokens JWT (JSON Web Tokens). Estos tokens contienen cabecera, payload con reclamos de identidad y una firma criptográfica para autenticar transacciones subsiguientes.

Registro de Usuario

curl -i -X POST http://10.0.2.4:8080/registration \
     -H "Content-Type: application/json" \
     -d '{"username":"vane", "password":"Password123"}'
Figura 4.1: Recepción de token JWT tras procesar la creación de usuario.

Exposición de Datos en /users

El endpoint /users carecía de controles de acceso a objetos (BOLA), retornando la lista interna de usuarios y sus hashes de autenticación:

curl -i http://10.0.2.4:8080/users
Figura 4.2: Volcado de cuentas donde se detecta al usuario 'patrick' y su hash PBKDF2-SHA256.

5. Análisis Criptográfico y Conclusiones

Fundamento Teórico: PBKDF2 aplica HMAC-SHA256 con un número elevado de rondas (29,000 iteraciones en este caso) incrementando deliberadamente el cómputo por cada intento de comparación, mitigando ataques de diccionario triviales en hardware genérico. 
john --format=pbkdf2-hmac-sha256 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
Figura 5.1: Cómputo limitado a ~573 c/s debido a las 29,000 iteraciones del algoritmo.

Conclusiones Técnicas

  • Fuga de Información Crítica: Endpoints con lectura pública no restringida que exponen identificadores de usuario y funciones resumen criptográficas.
  • Coste Criptográfico Elevado: La implementación de 29,000 iteraciones en PBKDF2 previene la resolución rápida sin aceleración por hardware o diccionarios altamente dirigidos.
  • Reglas de Métodos HTTP: El backend fuerza el uso de verbos específicos (POST vs GET) para validar solicitudes con estado de autorización.
